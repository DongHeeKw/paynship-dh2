# URL과 상품·통관 검토

## 2026-11-13 가격·옵션 확장

JSON-LD `ProductGroup.hasVariant`와 Product에서 SKU·모델·사이즈·색상·재질·판매자 원산지를 관측합니다. `selectObservedVariant`는 모든 선택 필드가 정확히 일치하는 단일 variant만 반환합니다. 조합을 추정하거나 최저가 variant를 대신 선택하지 않습니다. 여러 offer, AggregateOffer, 통화 없는 가격, 0/음수/범위 가격, 모호한 variant는 가격 확정에 사용하지 않습니다. 모호한 JSON-LD를 meta 가격으로 덮어쓰지 않습니다. 출처·시각·해시를 보존하고 포장 규격·HS·통관 승인을 추정하지 않습니다.

공개 `/purchase`에는 15%·최소 ₩10,000 수수료와 비용 항목을 표시합니다. 고객 입력 가격은 미검증 계산용이고 서버 견적에 쓰지 않습니다. 검토된 공개 catalog의 정확한 URL·옵션·국가·수량·최대 24시간 근거가 맞을 때만 자동 합계를 표시합니다. catalog는 초기 비어 있으며 임의 링크의 실시간 수집은 추가하지 않습니다. 신규 US/CN/JP 견적은 국가별 검증 관세·세금·통관비를 요구합니다. 기존 종가 산식을 세 나라의 완전한 세법 엔진으로 취급하지 않습니다. [가격 명세](../Pricing/Spec.md)를 따릅니다.

변경일: 2026-10-12. 고객 요청 중 모델 호출·외부 상품 수집·자동 HS 추론을 사용하지 않습니다. 운영자용 제한된 증거 수집 CLI는 별도로 제공합니다.

## URL 접수

`lib/purchases/product-url.ts`는 공유 정책 `lib/product-evidence/product-url.mjs`를 사용합니다. Coupang, Naver Smart Store/Brand, Musinsa, 29CM, Olive Young, Gmarket, Yes24, Kyobo의 정확한 HTTPS host와 상품 경로만 허용합니다. Yes24는 `www.yes24.com/product/goods/{숫자}`와 대소문자 변형, Kyobo는 `product.kyobobook.co.kr/detail/S{숫자}`입니다. 임의 host, 사용자 정보, 포트, 잘못된 상품 번호를 거절하며 불필요 query와 fragment를 정리합니다.

접수 중 외부 페이지를 가져오지 않습니다. 통과한 URL은 “지원하는 상품 주소 형태”이며 실제 상품 존재·재고·가격·수출 가능 여부가 아닙니다. 고객에게 검토 대기 상태를 반환합니다.

## 로그인 전 정보 확인

홈의 URL 입력은 로그인 상태와 관계없이 `/purchase`로 이동합니다. 공개 화면에서 URL·카테고리·수량·옵션·도착국을 입력하고 동일한 URL 정책, 초기 제외 카테고리, 기존 국가별 수취인 안내와 공식 자료 링크를 확인할 수 있습니다. 로그인은 실제 요청 저장·배송 프로필 입력 직전에 필요하며 공개 확인 자체는 DB나 고객 API를 호출하지 않습니다.

`lib/purchases/product-preview.ts`는 URL에서 파싱한 판매처·판매점 식별자·상품 번호·정규 상품 주소와 로컬 공개 상품 샘플의 수집 상태를 구분해 표시합니다. URL 정보는 주소에서 읽은 값이며 상품 페이지를 수집했다는 뜻이 아닙니다. 정규화한 상품 주소가 정확히 일치하고 수집 상태가 성공인 경우에만 상품명·판매처 가격·통화·과거 품절 관측값과 조회 시각을 표시합니다. 샘플 가격은 현재 판매가나 견적이 아니며 운임·관세·세금을 포함하지 않습니다. 샘플이 없거나 수집이 차단·실패된 URL에는 상품 정보를 모른다고 표시하고, 기존 수집 시도 기록이 있으면 날짜와 실패 원인을 안내합니다. 입력한 URL을 실시간 수집하거나 HS·재고·가격·통관 가능성을 추정하지 않습니다.

`lib/purchases/intake-draft.ts`는 URL·카테고리·수량·옵션·도착국만 strict schema로 sessionStorage에 저장합니다. 최대 UTF-8 4KiB, 보관 24시간이며 잘못된 국가·수량·예상 밖 필드·미래 저장 시각을 거절합니다. 동일 탭 OAuth 복귀와 배송 프로필 입력을 거쳐 상품 선택을 복원하고 실제 요청 제출 후 삭제합니다. 주소와 통관번호는 이 초안에 포함하지 않으며 상품 옵션에 개인정보를 넣지 않도록 안내합니다. 저장 주소 국가와 초안 도착국이 다르면 UI에서 제출을 막고 수정을 요구합니다. 서버는 별도로 실제 인증 사용자와 소유한 배송 프로필을 검증합니다.

개발 미리보기는 유효한 공개 초안을 마운트 후 한 번 읽어 사용하고, 없으면 빈 상품 입력으로 시작합니다. 읽기 전용 연결이므로 원래 초안을 수정·삭제하지 않으며 내부 화면 이동의 편집 값은 메모리에서 유지합니다. 예제 URL은 사용자가 직접 선택할 때만 입력합니다. 새로고침하면 미리보기 변경·생성 주문·문의는 초기화되지만 원래 공개 초안은 다시 읽을 수 있습니다.

`categories.ts`는 초기 서비스에서 식품·식물·동물성 제품·의약품·주류·담배를 제외합니다. 다른 카테고리도 모두 검토합니다. `countries.ts`의 선택 국가 목록은 접수 범위이며 자동 통관 승인 목록이 아닙니다.

## 검토 필드

운영자 검토는 `review-schema.ts`에서 구조를 검증합니다.

| 그룹 | 입력 |
| --- | --- |
| 상품 | 운영자 확인 카테고리·상품명·재질·원산지·가격·국내 배송비 |
| 운송 | 중량·치수·국제 운임·보험, 선택적 검증된 예상 운송 일수 |
| 분류·세금 | HS 세번, CIF/FOB 기준, 관세·세율 basis points, 관세의 세금 과표 포함 여부·추가 과표 |
| 금액 | KRW/USD 환율·대행 수수료 |
| 근거 | HTTPS 상품 증거 URL·공식 규칙 URL·검증 시각·만료 시각·통관 메모 |

규칙은 최근 30일 안에 검증하고 향후 30일 이내 만료되도록 제한합니다. 이 날짜 확인은 공식 자료의 정확성을 자동 판별하지 않습니다. 운영자가 도착국별 요구와 자료 내용을 확인할 책임이 있습니다.

## 계산

`quote.ts`는 운영자 승인 입력을 USD 정수 cents로 계산합니다.

- 상품·국내 배송비는 지정 환율로 환산하여 반올림합니다.
- 관세 과표는 FOB면 상품가, CIF면 상품가+국제 운임+보험입니다.
- 관세는 과표×승인된 basis points/10,000이며 cents로 반올림합니다.
- 도착국 세금은 승인 과표·추가 과표·필요 시 관세를 포함하여 계산합니다.
- 최종 금액은 상품·국내 운임·대행료·국제 운임·보험·관세·세금의 합입니다.

견적 유효기간은 최대 24시간이며 규칙 만료보다 늦을 수 없습니다. 검토 입력과 견적 버전을 보존합니다. 환급 VAT나 환차익으로 금액을 임의 차감하지 않습니다.

이 계산은 일반적인 종가 구조의 재현 가능한 산술입니다. 특정 국가의 모든 세목·종량세·최소세액·FTA·면세·수입 허가를 표현하지 못하면 적용하지 말고 거절·별도 검토합니다. 공식 요건이 없는 상태에서 세율을 추정해 결제를 열지 않습니다.

## 운영자 상품 증거 수집과 샘플

`npm run product:samples -- <상품 URL...>`은 공개 API와 분리된 운영자 CLI입니다. 한 번에 최대 10개 URL을 검증하고 중복을 제거한 뒤 동시성 1, 재시도 0으로 수집합니다. DNS와 HTTP 요청은 각각 8초, 응답은 최대 2MiB로 제한합니다. robots 정책을 먼저 확인하며, 사설·예약 IP를 거절하고 실제 HTTPS 연결을 검증한 DNS 주소에 고정합니다. TLS 검증을 유지하고 허용된 같은 host의 상품 경로로 한 번만 redirect를 허용합니다. 쿠키·로그인·브라우저 우회·모델 호출을 사용하지 않습니다.

JSON-LD의 Product/BreadcrumbList와 제한된 meta 태그만 관측합니다. 필드마다 값·추출 위치·원본 URL·조회 시각·원본 응답 SHA-256·`observed` 상태를 보존합니다. 다중 상품·다중 offer의 모호한 가격은 선택하지 않습니다. 이 결과는 검증된 상품·통관 승인이나 견적이 아니며, 없는 HS·원산지·포장 규격은 추정하지 않습니다.

2026-10-12 KST 실제 다섯 URL 중 Yes24 세 페이지에서 관측값을 얻었습니다. Musinsa는 robots 정책으로 차단됐고 Kyobo 응답은 지원하지 않는 형식으로 기록했습니다. 모든 결과는 `review_required`입니다. [JSON 및 재현 방법](../../../data/samples/README.md), [독립 SQLite 스키마와 검사](../../../data/samples/SAMPLE_DB.md)를 참고하세요. SQLite의 고객·주문·배송·CS 예제는 가상 데이터이며 실제 PostgreSQL·개인정보·결제에 접근하지 않습니다.

같은 날짜에 사용자 제공 Naver Brand 주소는 `https://brand.naver.com/kinox/products/5912828061`로 정규화했습니다. robots.txt 응답은 HTTP 200이었으며 정책 검사 결과는 `robots_blocked`입니다. 상품 페이지는 요청하지 않았고 상품명·가격·통관 필드는 미확인으로 남깁니다. [Naver 수집 시도 기록](../../../data/samples/naver-product-evidence-2026-10-12.json)은 URL 파싱 결과와 구분하며 수집 성공·통관 승인으로 사용하지 않습니다.
