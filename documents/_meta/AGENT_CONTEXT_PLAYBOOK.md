# Agent context playbook

1. Read `AGENTS.md`, this file, `REGISTRY.yaml` and `README.md`.
2. Load only the current feature and operations documents needed for the change.
3. A dated plan is working context; it never overrides the current product and security specifications.
4. Update code, current specs and implementation status together. Record the actual validation performed.
5. Split file ownership when working in parallel. Avoid editing another agent's module.
6. Use portable relative links, never another developer's absolute machine path.
7. Retain current primary sources and dates for external legal or carrier claims.
8. Treat URL validation, product evidence, customs rules and payment confirmation as separate decisions. Missing information requires review or rejection.
9. Preserve historical database tables without reactivating retired endpoints. Old plans, mocks and archived test reports do not prove production readiness.
10. Keep root entry files concise. Security, warehouse, tax and deployment guidance belongs in the corresponding current document.

Current sources: [registry](REGISTRY.yaml). Documentation policy: [governance](DOC_GOVERNANCE.md).
