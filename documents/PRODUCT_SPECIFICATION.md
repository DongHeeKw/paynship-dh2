# 제품 기준

변경일: 2026-10-12.

PayNShip은 한국 판매처에서 해외 고객 대신 상품을 구매하고 국제 배송을 관리합니다. 아시아권과 미국을 포함한 여러 국가의 요청을 받지만 국가 선택 목록이 배송·통관 지원 보장을 뜻하지는 않습니다.

## 고객 흐름

1. 상품 URL을 입력하면 로그인 없이 상품 입력 화면으로 이동합니다.
2. 카테고리·옵션·수량·도착국을 선택하고 URL에서 파싱한 판매처·판매점 식별자·상품 번호·정규 주소, 사업 범위와 해당 국가의 수취인 요건을 확인합니다. 정확히 일치하는 수집 샘플은 조회 시각을 명시한 과거 관측값만 보여주며, 수집 차단·실패는 미확인 정보로 안내합니다.
3. 요청을 저장할 때 이메일 인증 계정으로 로그인하고 배송 프로필을 저장한 뒤 구매 요청을 제출합니다. 선택한 도착국과 저장 주소 국가가 다르면 제출 전 주소 또는 선택 국가를 수정해야 합니다.
4. 본인 요청의 검토·견적·결제·구매·입고·출고·배송 현황을 확인합니다.
5. 검토된 견적이 있으면 외부 결제 페이지로 이동합니다.
6. 해당 요청에 문의를 남기고 운영자 답변을 확인합니다.

실제 운송장·이벤트가 없으면 배송 예정일이나 배송 완료를 만들어 보여주지 않습니다. 제출은 구매 계약 확정이나 국내 판매처 발주가 아닙니다.

로그인 전 상품 초안은 같은 브라우저 탭의 sessionStorage에 4KiB 이내로 저장하며 24시간 뒤 만료됩니다. 초안 필드는 URL·카테고리·수량·상품 옵션·도착국뿐이며 배송 주소·통관 식별자 필드를 포함하지 않습니다. 옵션에 개인정보를 입력하지 않도록 안내합니다. 브라우저 저장소가 차단되면 로그인 이동 전 저장 실패를 알립니다. 이 공개 화면은 서버 인증을 우회하거나 실제 구매 요청을 생성하지 않습니다.

개발 미리보기에서도 같은 탭의 유효한 상품 초안을 한 번 읽어 이어가고 없으면 빈 입력으로 시작합니다. 상품 예제는 직접 선택해야 하며 입력 URL을 예제로 덮어쓰지 않습니다. 원래 공개 초안은 수정·삭제하지 않고, 미리보기의 상품 편집·배송정보·생성 요청·문의는 메모리에서만 변경합니다. 화면 이동은 편집 값을 유지하지만 새로고침하면 변경은 초기화되고 원래 공개 초안을 다시 읽습니다. 예제 요청·배송은 가상 데이터로 표시하며 실제 서버 데이터와 연결하지 않습니다.

## 운영 흐름

운영자는 서버 권한 검증 후 요청 목록과 상세 배송정보를 조회합니다. 상품 실재·옵션·재고·가격·재질·원산지·중량·치수·HS 분류·도착국 요건을 증빙과 함께 검토하고 승인된 입력으로 견적을 계산합니다.

결제는 서명 webhook으로 확인합니다. 이후 국내 구매 → 창고 입고 → 검수·포장 → 배송사 인계 → 배송 현황을 기록합니다. 주문 상태와 CS는 같은 요청을 기준으로 관리합니다. 관리 화면은 이 업무에 필요한 목록·상세만 남깁니다.

## 범위와 한계

- 대화형 AI, 모델 API, 상품 검색 에이전트, 고객 대시보드, Docker 개발 실행은 제거합니다.
- 고객 제출은 URL의 host·상품 경로만 확인합니다. 별도 운영자 증거 CLI로 공개 페이지 샘플을 수집할 수 있으며 가격·재고·통관 누락 사항은 검토가 필요합니다.
- 식품·식물·동물성 제품·의약품·주류·담배는 초기 사업 범위에서 제외합니다. 법적으로 모든 국가에서 금지라는 뜻은 아닙니다.
- 고객 카테고리는 사실 확인을 대체하지 않습니다. 허위 분류는 운영자 검토에서 거절합니다.
- 정적 견적은 운영자가 검증한 CIF/FOB 가격 기준·종가 관세율·세율로 계산합니다. 국가별 복잡한 종량세·추가 규제·면세 규칙을 자동 구현한 엔진은 아닙니다.
- 실시간 배송은 제공자별 adapter가 실제 이벤트를 정규화하여 서명 gateway로 전달해야 합니다. 코드 계약만으로 외부 계약이 완료되지 않습니다.
- 고객 통관 식별자는 도착국의 실제 요구에 맞게 사용합니다. 모든 해외 사용자에게 한국 개인통관고유부호를 요구하지 않습니다.
- [국가별 정책](Reference/COUNTRY_CUSTOMS.md)은 개인정보를 최소 수집하고 형식 검사와 실제 증빙 검토를 분리합니다. 선택 가능한 국가 수와 출시 지원 국가는 다릅니다.

## 데이터

| 신규 모델 | 책임 |
| --- | --- |
| `DeliveryProfile` | 고객별 암호화 배송 프로필 |
| `PurchaseRequest` | URL·옵션·수량·도착국·암호화 배송 스냅샷·검토·견적·결제·송장·상태·버전 |
| `PurchaseEvent` | 고객·운영자·제공자 상태 기록 |
| `PurchaseSupportTicket` | 요청에 연결된 암호화 문의·답변·처리 상태 |
| `PurchaseQuota` | 계정·전체의 기간별 처리량 |
| `PurchaseWebhookReceipt` | 결제·배송 이벤트 중복 수신 방지 |

기존 Prisma 모델은 과거 데이터 보존을 위해 유지합니다. 새 SQL은 테이블 추가와 앱 테이블의 RLS·브라우저 권한 차단을 포함합니다. 실제 원격 DB에 적용했다고 가정하지 않습니다.

과거 API는 middleware에서 410으로 차단하고 과거 관리 화면은 구매 관리로 이동합니다. 운영자의 상태 변경·결제 대조·수취인 근거 업데이트는 별도 action이며 결제 이후 금액과 진행한 구매 단계를 임의 초기화하지 않습니다. 배송 완료는 서명된 실제 배송 이벤트로만 표시합니다.
