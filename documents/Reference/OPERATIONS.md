# 구매·창고·배송·CS 운영

> **<u>V3 자동화 목표는 수동 물류 작업을 나중에 처리하는 것이 아니라 자동 의사결정 엔진을 우선 구현하는 것이다.</u>** [AUTO-ENGINE 알고리즘·운영 절차](../2027/AUTO_ENGINE_ALGORITHMS_AND_WORK_PROCESS.md)를 우선한다. 판매처·3PL·합배송·관세/DDP·국제배송사/서비스는 실제 계약과 입고·운임 증거를 바탕으로 후보 전체를 비교한다. 현재 운영절차는 기존 상태이며 자동 최적화·실발주까지 구현됐다는 뜻은 아니다.

> **현재 운영 vs 2027 목표:** 이 문서의 창고/배송 절차는 현행 수동·검증 중심이며 실제 배송사 연동과 자동 합배송이 완료된 것은 아닙니다. 목표 계약과 운영 테스트는 [V3 SRS](../2027/INTEGRATED_SRS.md), [배송/추적 테스트](../2027/TEST_MATRIX.md), [에이전트 실행 순서](../2027/AGENT_IMPLEMENTATION_PLAN.md)를 따릅니다. 고객에게는 배대지·택배사 내부 선택을 요구하지 않는 것을 목표로 하지만 실비, 관세 부담자, 배송 지연, 통관 보류, 환불 권리는 명확하게 공개합니다.

## 초기 실제 운영: 자택 HOME_HUB가 배대지 역할

**<u>초기 PayNShip은 사업주가 자신의 집에서 국내 택배를 수령하고, 검수·보관·합포장·출고하는 자택 허브(Home Hub) 모델을 기본으로 한다.</u>** 3PL 계약은 초기 필수조건이 아니며 주문량/실비/시간 대비 효율이 높아지는 시점에 도입한다. [HOME_HUB_AND_CONSOLIDATION_SRS.md](../2027/HOME_HUB_AND_CONSOLIDATION_SRS.md)는 국내 운송장 입고, 실측, 고객별 보관함, 다중 주문 합배송 추천, 추가 대기일·절감액, 동의, 실제 출고, 미지원/파손/통관 보류와 TDD 요구사항을 정의한다. 자택 운영의 법적 적합성, 주소·개인정보 공개 최소화, 반품 및 보험, 국내/국제 집하 조건은 사전에 확인한다.

**합배송이 핵심 자동화:** 동일 수취인의 주문이 2개 이상이면 시스템이 각각/전체/부분/대기 합배송 후보를 비교하고 고객에게 **얼마 절약하는지 + 며칠 더 기다리는지** 제안한다. 이미 약속한 배송기한과 비용을 고객 동의 없이 악화시키지 않는다. 실제 운송사·세관·DDP 근거가 없으면 절감액을 확정 표시하지 않는다.

## 창고가 필요한 이유

과거 master plan은 국내 판매처에서 구매해 AcrossB 한국 창고로 보내고, 입고·검수·재포장 후 해외 출고하는 모델이었습니다. 이 물리 업무는 화면을 단순하게 바꾸어도 필요합니다.

회사 소유 창고가 필수라는 뜻은 아닙니다. 계약된 3PL 또는 배송대행 창고에 입고·검수·보관·포장·출고를 맡길 수 있습니다. 직접 운영한다면 작업 공간, 보관·분실 책임, 인력과 국내 반품 주소를 마련해야 합니다. 판매처 직배송을 이용할 경우에도 실측·검수·수출 증빙 책임을 계약으로 명시해야 합니다.

| 단계 | 운영자가 확인하고 남길 것 |
| --- | --- |
| 상품 검토 | 정확한 상품·옵션·가격, 증빙, 도착국 제한, HS 근거 |
| 견적 | 승인 정책·환율, 항목별 가격, 유효기간, 비용 부담자 |
| 결제 확인 | 서명 webhook, 금액·통화·주문 매칭 |
| 국내 구매 | 판매처 주문번호, 실제 매입금액, 품절·가격 변동 |
| 입고·검수 | 상품·옵션·수량, 손상, 사진, 실제 무게·크기 |
| 포장·출고 | 포장 규격, 신고 자료, 운송장, 인계 증빙 |
| 국제 배송 | 배송사 출처·갱신 시간, 통관 보류·배송 예외 |
| 고객 문의 | 요청별 문의·답변·상태, 담당자, 필요 증빙 |

추측한 배송 예정일이나 스캔되지 않은 배송 완료를 표시하지 않습니다. 실제 주문 상태·송장과 갱신 출처를 보여줍니다.

## 취소와 환불

결제 전 검토·견적 상태에서만 고객이 직접 취소합니다. 결제 시작 후에는 CS 요청으로 처리합니다. 구매·발송 중 취소 가능성과 비용은 판매처·운송사·약관에 따라 달라집니다.

반복 취소는 하루 할당량에 포함합니다. 이미 취소된 요청의 재시도는 다시 처리하지 않습니다. 결제 후 환불 완료는 제공자 확인이 있어야 하며 운영자가 상태만 바꿔 완료로 만들지 않습니다.

환불 API, 판매처 반품, 회수 배송, 차지백·정산 대조는 출시 전 남은 업무입니다. ON_HOLD는 자동 구매·출고를 중단하며 원인 조사·복구 근거가 필요합니다.

## CS와 계약

고객은 본인 요청에 문의를 남기고 운영자는 답변·처리 상태를 기록합니다. 자유 입력란에 카드 번호, 비밀번호, 다른 사람의 정보를 넣지 않도록 안내합니다.

메일·메신저 알림, 다국어 대응, 첨부 사진 접근 통제, 보존·삭제와 응답 SLA는 별도로 구성해야 합니다. 인력·영업시간을 정하기 전 24시간 응대를 약속하지 않습니다.

먼저 판매국 한 곳과 저위험 상품 범위로 실제 주문을 끝까지 검증한 뒤 범위를 확장합니다.

- 수출자·수입자·대행자 역할과 관세사 책임을 확정합니다.
- 창고 또는 3PL의 검수·보관·분실·반품·사진 개인정보 계약을 확정합니다.
- 국제 배송 계약, 운임, 위험물 제한, 사고 보상과 webhook 서명을 확인합니다.
- 결제·환불·정산과 개인정보 보존·삭제를 검증합니다.
- 1인 운영의 하루 처리 가능량과 전체 요청 할당량을 맞춥니다.

운송장 입력과 이벤트를 보여주는 코드가 있어도 배송사 gateway·계약 연결을 검증하기 전 실시간 연동 완료로 표시하지 않습니다.

## 가격 운영 (2026-11-13)

**현재 신규 주문에는 상품 소계 15%, 최소 수수료 없이 적용**하고 (과거 결제 완료 견적의 15%/₩10,000 최소 규정은 이력으로 보존), 배송·수입 비용은 분리합니다. 수수료는 순이익이 아닙니다. 초기 30건의 작업 시간·결제/환전·포장·환불/오류 비용을 기록합니다. 현재 한 요청은 한 상품/수량의 판매처 주문입니다. **V3 목표**는 여러 구매 요청을 안전하게 연결한 다상품 주문 및 국제 합배송/분할배송 구조입니다. 실제 구현 전에는 상품 여러 개 주문을 지원한다고 안내하지 않습니다. 여러 요청을 실제 묶음 구매하면 중복 최소 수수료를 막는 grouping/refund 절차가 먼저 필요합니다.

공개 catalog는 개인정보 없는 검토 자료만 게시하고 최대 24시간 만료를 관리합니다. 초기에는 비어 있습니다. 새로운 US/CN/JP 견적은 국가·품목·원산지·운송 경로별 관세/세금/통관비 평가액을 확인해 입력합니다. 배송사/관세사 근거 없이 generic 세율이나 고객 입력 가격으로 결제를 열지 않습니다. [가격·자료 게시 명세](../Features/Pricing/Spec.md)를 따릅니다.
