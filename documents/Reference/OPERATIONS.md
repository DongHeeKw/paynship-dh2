# 구매·창고·배송·CS 운영

## 창고가 필요한 이유

기존 master plan은 국내 판매처에서 구매해 AcrossB 한국 창고로 보내고, 입고·검수·재포장 후 해외 출고하는 모델이었습니다. 이 물리 업무는 화면을 단순하게 바꾸어도 필요합니다.

회사 소유 창고가 필수라는 뜻은 아닙니다. 계약된 3PL 또는 배송대행 창고에 입고·검수·보관·포장·출고를 맡길 수 있습니다. 직접 운영한다면 작업 공간, 보관·분실 책임, 인력과 국내 반품 주소를 마련해야 합니다. 판매처 직배송을 이용할 경우에도 실측·검수·수출 증빙 책임을 계약으로 명시해야 합니다.

| 단계 | 운영자가 확인하고 남길 것 |
| --- | --- |
| 상품 검토 | 정확한 상품·옵션·가격, 증빙, 도착국 제한, HS 근거 |
| 견적 | 승인 정책·환율, 항목별 가격, 유효기간, 비용 부담자 |
| 결제 확인 | 서명 webhook, 금액·통화·주문 매칭 |
| 국내 구매 | 판매처 주문번호, 실제 매입금액, 품절·가격 변동 |
| 입고·검수 | 상품·옵션·수량, 손상, 사진, 실제 무게·크기 |
| 포장·출고 | 포장 규격, 신고 자료, 운송장, 인계 증빙 |
| 국제 배송 | 배송사 출처·갱신 시간, 통관 보류·배송 예외 |
| 고객 문의 | 요청별 문의·답변·상태, 담당자, 필요 증빙 |

추측한 배송 예정일이나 스캔되지 않은 배송 완료를 표시하지 않습니다. 실제 주문 상태·송장과 갱신 출처를 보여줍니다.

## 취소와 환불

결제 전 검토·견적 상태에서만 고객이 직접 취소합니다. 결제 시작 후에는 CS 요청으로 처리합니다. 구매·발송 중 취소 가능성과 비용은 판매처·운송사·약관에 따라 달라집니다.

반복 취소는 하루 할당량에 포함합니다. 이미 취소된 요청의 재시도는 다시 처리하지 않습니다. 결제 후 환불 완료는 제공자 확인이 있어야 하며 운영자가 상태만 바꿔 완료로 만들지 않습니다.

환불 API, 판매처 반품, 회수 배송, 차지백·정산 대조는 출시 전 남은 업무입니다. ON_HOLD는 자동 구매·출고를 중단하며 원인 조사·복구 근거가 필요합니다.

## CS와 계약

고객은 본인 요청에 문의를 남기고 운영자는 답변·처리 상태를 기록합니다. 자유 입력란에 카드 번호, 비밀번호, 다른 사람의 정보를 넣지 않도록 안내합니다.

메일·메신저 알림, 다국어 대응, 첨부 사진 접근 통제, 보존·삭제와 응답 SLA는 별도로 구성해야 합니다. 인력·영업시간을 정하기 전 24시간 응대를 약속하지 않습니다.

먼저 판매국 한 곳과 저위험 상품 범위로 실제 주문을 끝까지 검증한 뒤 범위를 확장합니다.

- 수출자·수입자·대행자 역할과 관세사 책임을 확정합니다.
- 창고 또는 3PL의 검수·보관·분실·반품·사진 개인정보 계약을 확정합니다.
- 국제 배송 계약, 운임, 위험물 제한, 사고 보상과 webhook 서명을 확인합니다.
- 결제·환불·정산과 개인정보 보존·삭제를 검증합니다.
- 1인 운영의 하루 처리 가능량과 전체 요청 할당량을 맞춥니다.

운송장 입력과 이벤트를 보여주는 코드가 있어도 배송사 gateway·계약 연결을 검증하기 전 실시간 연동 완료로 표시하지 않습니다.
