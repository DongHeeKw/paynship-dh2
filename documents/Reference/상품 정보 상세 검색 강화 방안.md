# **차세대 이커머스 데이터 파이프라인: 검색 AI 기반 상품 속성 증강 및 크로스보더 최적화 전략 보고서**

## **1\. 서론: 이커머스 데이터 완전성과 알고리즘 기반 물류의 진화**

현대 글로벌 이커머스 생태계, 특히 한국의 쿠팡(Coupang)과 네이버 스마트스토어(Naver SmartStore)를 중심으로 한 마켓플레이스 환경에서 상품 데이터의 완전성(Data Completeness)은 단순한 소비자 정보 제공의 차원을 넘어섰다. 이는 플랫폼의 검색 랭킹 알고리즘(SEO)을 결정짓는 핵심 변수이자, 크로스보더(Cross-Border) 물류 비용의 최적화 및 관세 컴플라이언스(HS Code Compliance)를 좌우하는 운영 효율성의 척도로 자리 잡았다. 그러나 수많은 셀러가 직면하는 고질적인 문제는 제조사나 도매처로부터 제공받는 원천 데이터에 무게(Weight), 부피(Volume), 재질(Material), HS 코드(HS Code), 원산지(Origin)와 같은 필수 백엔드 속성이 빈번하게 누락되어 있다는 점이다.1 이러한 데이터의 공백은 물류비 과소 산정으로 인한 마진 잠식, 통관 지연에 따른 고객 경험 악화, 그리고 플랫폼 내 카테고리 매칭 실패로 인한 노출 저하라는 연쇄적인 비즈니스 리스크를 초래한다.

기존의 데이터 보강 방식은 인력에 의존한 수동 검색이나, 정해진 규칙에 따라 특정 사이트를 크롤링하는 스크래핑(Scraping) 방식에 머물렀다. 그러나 이러한 접근은 웹사이트 구조 변경에 취약하고, 비정형 텍스트(Unstructured Text) 내에 숨겨진 정보를 추출하는 데 한계를 보인다. 이에 따라 최근 등장한 LLM(Large Language Model) 최적화 검색 엔진인 **Tavily API**와 같은 도구는 웹상의 방대한 정보를 실시간으로 탐색하고, 맥락을 파악하여 정형 데이터로 합성(Synthesis)하는 새로운 패러다임을 제시한다.3

본 보고서는 Tavily API와 같은 지능형 검색 모듈을 활용하여 쿠팡 및 네이버 등 주요 플랫폼에서 요구하는 누락된 상품 정보를 자동으로 보강하는 엔지니어링 전략을 심층적으로 분석한다. 특히, 단순히 정보를 검색하는 것을 넘어, **(1) 속성별 최적화된 쿼리 패턴 엔지니어링(Query Pattern Engineering)**, **(2) 신뢰도 기반의 도메인 타겟팅 전략(Domain Targeting)**, 그리고 **(3) 추출된 데이터의 정합성을 검증하고 플랫폼 API 규격에 맞춰 변환하는 파이프라인 아키텍처**를 포괄적으로 제시함으로써, 이커머스 데이터 운영의 자동화와 고도화를 위한 실질적인 가이드라인을 제공하고자 한다.

## **2\. 검색 모듈 기반 데이터 증강 아키텍처 및 Tavily API 심층 분석**

### **2.1 지능형 검색 파이프라인의 구조적 설계**

누락된 상품 정보를 보강하는 시스템은 단순한 키워드 검색을 넘어, 쿼리 생성부터 데이터 정규화에 이르는 다단계 파이프라인으로 설계되어야 한다. 이는 LLM 에이전트(Agent)가 검색 도구를 활용하여 비정형 데이터를 수집하고, 이를 다시 정형 데이터로 가공하는 '에이전틱 워크플로우(Agentic Workflow)'를 기반으로 한다.5

이 파이프라인의 핵심은 \*\*검색의 정확도(Precision)\*\*와 **데이터의 재현율(Recall)** 사이의 균형을 맞추는 것이다. Tavily API는 이러한 균형을 맞추기 위해 일반 검색 엔진과 달리 AI 에이전트 전용으로 설계되었으며, 불필요한 HTML 마크업이나 광고 스크립트를 제거하고 LLM이 해석 가능한 깨끗한 텍스트 데이터만을 반환하는 특징이 있다.7 따라서 전체 아키텍처는 다음과 같은 논리적 흐름을 따른다.

1. **쿼리 확장 및 생성 (Query Expansion):** 상품명(Product Name)과 브랜드(Brand) 같은 기본 정보를 바탕으로, 찾고자 하는 특정 속성(예: Shipping Weight)을 결합한 다수의 구체적 쿼리를 생성한다.  
2. **도메인 필터링 검색 (Targeted Search):** 정보의 신뢰도가 낮은 블로그나 커뮤니티를 배제하고, 제조사 공식 홈페이지, 대형 리테일러, 규제 기관 등 검증된 도메인(include\_domains)으로 검색 범위를 한정한다.8  
3. **심층 콘텐츠 추출 (Deep Content Extraction):** 검색 결과의 요약본(Snippet)만으로는 세부 스펙을 확인하기 어렵기 때문에, include\_raw\_content=True 옵션을 활성화하여 페이지 전체 텍스트를 확보한다.7  
4. **속성 추출 및 검증 (Extraction & Validation):** LLM을 활용하여 원문 텍스트 내에서 수치와 단위를 식별하고, 상충하는 데이터(예: 서로 다른 무게 값)가 있을 경우 신뢰도 점수(Score)에 따라 최적의 값을 선택한다.

### **2.2 Tavily API 파라미터 최적화 및 기술적 제언**

성공적인 데이터 증강을 위해서는 Tavily API의 파라미터를 목적에 맞게 정밀하게 튜닝해야 한다. 본 연구에서 분석한 연구 자료들에 따르면, 각 파라미터는 검색 비용과 데이터 품질에 직접적인 영향을 미친다.3

| 파라미터 (Parameter) | 최적 설정 값 (Recommended Configuration) | 기술적 근거 및 활용 전략 |
| :---- | :---- | :---- |
| **search\_depth** | "advanced" | 기본(basic) 모드는 빠른 응답을 제공하지만, 상품의 상세 스펙(예: HS Code, 내부 재질)은 주로 페이지의 하단이나 별도의 탭에 숨겨져 있다. "advanced" 모드는 더 깊은 크롤링을 수행하여 이러한 "Deep Web" 정보를 포착할 확률을 높인다.4 |
| **include\_domains** | \["amazon.com", "manualslib.com", "customs.go.kr",...\] | 검색 결과의 노이즈를 획기적으로 줄이는 핵심 기능이다. 속성별(무게, HS 코드 등)로 화이트리스트 도메인을 동적으로 교체하는 전략을 사용하여 할루시네이션(Hallucination) 위험을 최소화한다.8 |
| **include\_raw\_content** | True | 단순 요약문에는 "무게: 1kg" 정도만 나오지만, 원문에는 "Item Weight: 1kg, Shipping Weight: 1.5kg"와 같이 구체적인 문맥이 포함된다. 물류비 산정에는 'Shipping Weight'가 필수적이므로 원문 분석이 불가피하다.7 |
| **max\_results** | 5 \~ 7 | LLM의 컨텍스트 윈도우(Context Window) 한계를 고려할 때, 너무 많은 검색 결과는 오히려 정확도를 떨어뜨린다. 상위 5\~7개의 신뢰도 높은 소스만으로 교차 검증(Cross-referencing)을 수행하는 것이 효율적이다. |
| **topic** | "general" | 상품 정보는 뉴스(news)나 금융(finance) 카테고리에 속하지 않으므로 "general"로 설정하되, 특정 국가(예: 한국향 제품)의 정보가 필요할 경우 country 파라미터를 활용해 로컬 데이터를 우선순위화한다.4 |

이러한 파라미터 설정은 정적인 것이 아니라, 1차 검색 실패 시 include\_domains를 확장하거나 search\_depth를 조정하는 등 동적으로 제어되어야 한다. 예를 들어, 아마존에서 정보를 찾지 못한 경우, 2차적으로 이베이(eBay)나 월마트(Walmart) 도메인을 추가하여 재검색을 수행하는 식이다.

## **3\. 속성별 구체적 검색 전략 및 쿼리 패턴 엔지니어링**

데이터의 종류에 따라 정보가 존재하는 위치와 형식이 다르므로, 속성별로 특화된 검색 전략과 쿼리 패턴을 적용해야 한다. 이는 검색 엔진이 사용자의 의도를 정확히 파악하게 유도하는 '프롬프트 엔지니어링'의 검색 버전이라 할 수 있다.

### **3.1 무게(Weight) 및 부피(Volume) 정보 보강**

무게와 부피는 물류비(Shipping Cost)를 결정짓는 가장 중요한 변수이다. 특히 항공 운송 시 적용되는 '부피 무게(Volumetric Weight)'를 계산하기 위해서는 가로, 세로, 높이의 정확한 치수(Dimensions)가 필수적이다.

#### **검색 전략의 핵심: Gross vs. Net 구분**

많은 상품 페이지가 제품 자체의 무게(Net Weight)와 포장을 포함한 배송 무게(Gross/Shipping Weight)를 혼용해서 표기한다. 물류 관점에서는 **Shipping Weight**가 중요하므로, 쿼리 생성 시 이를 명시해야 한다.12

* **쿼리 패턴 (Query Patterns):**  
  * "{Brand} {Product Name} shipping weight package dimensions"  
  * "{Model Number} gross weight vs net weight specifications"  
  * "site:amazon.com {Product Name} technical details item dimensions"  
  * "{Product Name} specification sheet pdf"  
* **추출 로직 및 데이터 검증:**  
  * Tavily의 raw\_content에서 Shipping Weight, Package Dimensions 키워드 주변의 수치를 우선적으로 추출한다.  
  * 추출된 수치의 단위가 lbs, oz, kg, g 중 무엇인지 정규식(Regex)으로 파싱하여 표준 단위(예: kg)로 변환한다.15  
  * 만약 복수의 무게 정보가 발견될 경우, 물류 안전성을 위해 가장 큰 값을 채택하는 **Max-Value Heuristic**을 적용하거나, LLM에게 "배송 무게로 가장 적절한 값은 무엇인가?"라고 질의하여 판단하게 한다.

### **3.2 재질(Material) 및 성분 정보 보강**

재질 정보는 상품의 내구성뿐만 아니라, 통관 시 관세율을 결정하는 HS Code 분류의 핵심 기준이 된다. 또한, 유아용품이나 식기류의 경우 KC 인증 대상 여부를 판단하는 근거가 되기도 한다.

* **쿼리 패턴 (Query Patterns):**  
  * "{Product Name} material composition fabric content" (의류/섬유)  
  * "{Product Name} full ingredients list" (화장품/식품)  
  * "{Product Name} safety data sheet (SDS) material" (화학/배터리)  
  * "{Product Name} housing material metal or plastic" (전자기기)  
* **검색 전략 및 유용 사이트:**  
  * **화학/안전 정보:** 제품이 배터리를 포함하거나 화학 물질인 경우, MSDS (Material Safety Data Sheet) 또는 SDS 키워드를 포함하여 검색하면 제조사가 배포한 안전 보건 자료 PDF를 찾을 수 있다. 이는 재질 정보를 가장 정확하게 담고 있는 문서이다.16  
  * **리뷰 기반 추론:** 제조사 스펙에 재질이 명시되지 않은 경우, 사용자 리뷰("The frame feels like aluminum, not plastic")를 분석하여 재질을 역추적할 수 있다. Tavily로 리뷰 데이터를 수집하고 LLM으로 감성 분석 및 팩트 추출을 수행한다.17

### **3.3 HS CODE 및 원산지(Origin) 자동 분류**

HS CODE(Harmonized System Code)는 국제 무역의 언어이다. 전 세계적으로 앞 6자리는 공통이지만, 한국 수입 통관을 위해서는 10자리(HKT)까지 확정해야 한다. 원산지 정보는 FTA 협정세율 적용 여부를 결정짓는다.

#### **HS CODE 분류의 난이도와 해결책**

HS CODE는 상품의 용도, 재질, 가공 정도에 따라 매우 복잡하게 분류된다. 단순히 상품명만으로는 정확한 코드를 찾기 어렵다. 따라서 상품의 \*\*상세 설명(Description)\*\*과 **이미지 정보**를 결합한 멀티모달 접근이 필요하다.18

* **쿼리 패턴 (Query Patterns):**  
  * "{Product Name} HS code harmonized code"  
  * "{Product Name} customs ruling tariff classification"  
  * "{Product Name} country of origin label"  
  * "{Brand} manufacturing factory location"  
* **유용한 사이트 및 데이터 소스:**  
  * **관세청 및 분류 서비스:** findhs.codes, customs.go.kr (한국 관세청), usitc.gov (미국 국제무역위원회) 등의 도메인은 관세 분류 사례와 세율 정보를 제공한다. 특히 미국의 CROSS (Customs Rulings Online Search System) 데이터베이스는 특정 상품에 대한 법적 분류 판례를 제공하므로 매우 신뢰도가 높다.19  
  * **AI 기반 분류:** Zonos Classify 20나 Avalara 21와 같은 전문 솔루션의 API를 활용하거나, 수집된 상품 설명을 바탕으로 LLM에게 "이 제품은 \[재질\]로 된 \[용도\]의 물건이다. 한국 관세율표 기준 6자리 HS 코드를 추천해달라"고 프롬프팅하는 방식을 사용한다.  
  * **유사 상품 벤치마킹:** 아마존이나 이베이에서 유사한 카테고리의 베스트셀러 상품이 사용하는 HS CODE를 역추적하여 벤치마킹한다.

## **4\. 검색 대상이 될 유용한 사이트 조사 및 데이터 소스 계층화**

효율적인 검색을 위해서는 정보의 질과 특성에 따라 데이터 소스를 계층화(Tiering)하여 관리해야 한다. Tavily API의 include\_domains 파라미터에 이들 도메인을 적절히 배합하여 사용한다.

### **4.1 Tier 1: 글로벌 이커머스 및 마켓플레이스 (Structured Metadata)**

가장 방대한 상품 데이터를 보유하고 있으며, 특히 물류 데이터(무게, 부피)가 정형화된 메타데이터 형태로 제공된다.

| 사이트 명 | URL | 주요 제공 정보 | 활용 전략 |
| :---- | :---- | :---- | :---- |
| **Amazon (US/JP/DE)** | amazon.com | Shipping Weight, Dimensions, ASIN, Origin | 'Product Information' 섹션의 HTML 구조가 일관되어 파싱이 용이함. 패키지 무게와 본품 무게를 명확히 구분함.12 |
| **eBay** | ebay.com | UPC, EAN, Item Specifics | 셀러들이 직접 입력한 희귀 속성 정보나 바코드(GTIN) 정보를 얻기에 유리함. 희귀품이나 중고품 정보 보강에 적합.24 |
| **AliExpress / Alibaba** | aliexpress.com | Packaging Details, HS Code (CN) | 중국 발 소싱 제품의 포장 규격 및 중국 측 수출 HS Code 확인 가능. |
| **Walmart** | walmart.com | Specifications, Assembled Weight | 아마존에 없는 공산품이나 식료품의 상세 스펙 교차 검증용. |

### **4.2 Tier 2: 기술 문서 및 매뉴얼 저장소 (Technical Specs)**

리테일 사이트에서 누락된 심층적인 기술 사양, 회로도, 정확한 부품 재질 정보를 제공한다.

## **5\. 고급 검색 및 추출 알고리즘 (Search & Extraction Algorithms)**

검색된 정보의 품질을 보장하고, 이를 플랫폼 API에 연동 가능한 형태로 가공하기 위한 기술적 알고리즘이다.

### **5.1 엔티티 해결 (Entity Resolution) 및 상품 매칭**

검색의 가장 큰 리스크는 유사하지만 다른 상품(예: iPhone 13 vs iPhone 13 Pro)의 정보를 가져오는 것이다. 이를 방지하기 위해 엄격한 상품 매칭 알고리즘이 필요하다.28

* **식별자 우선 매칭:** GTIN, UPC, EAN, ISBN, MPN(Manufacturer Part Number)이 존재하면 이를 최우선 매칭 키(Key)로 사용한다. 이는 동명이인 오류를 방지하는 가장 확실한 방법이다.  
* **유사도 검증 (Similarity Check):** 검색된 페이지의 상품명과 원본 상품명 간의 **자카드 유사도(Jaccard Similarity)** 또는 \*\*코사인 유사도(Cosine Similarity)\*\*를 계산하여, 임계값(예: 0.85) 이상인 정보만 신뢰한다.  
* **이미지 기반 검증:** 멀티모달 LLM(예: GPT-4V)을 활용하여 원본 썸네일과 검색된 상품 이미지를 시각적으로 비교, 동일 상품 여부를 2차 검증한다.31

### **5.2 데이터 정규화 및 단위 변환 (Normalization)**

수집된 데이터는 국가별로 단위가 상이하므로(미국: lbs/inch, 한국: kg/cm), 이를 표준화하는 로직이 필수적이다.

* **단위 추출 정규식:** (\\d+(\\.\\d+)?)\\s\*(lbs?|pounds?|kg|g|oz)와 같은 정규식을 사용하여 수치와 단위를 분리한다.15  
* **변환 공식:**  
  * 1 lb \= 0.453592 kg  
  * 1 oz \= 0.0283495 kg  
  * 1 inch \= 2.54 cm  
* **이상치 탐지 (Sanity Check):** 카테고리별 평균 데이터 분포를 기반으로, 추출된 값이 터무니없이 크거나 작을 경우(예: 이어폰 무게가 5kg) 오류로 간주하고 재검색 프로세스를 트리거한다.

### **5.3 쿠팡/네이버 API 연동을 위한 매핑**

최종 데이터는 각 플랫폼의 API 스펙에 맞춰 포맷팅되어야 한다.1

* **쿠팡 (Coupang Wing API):** attributes 필드 내에 attributeTypeName(속성명)과 attributeValueName(속성값) 객체 형태로 주입한다. 예를 들어, {"attributeTypeName": "개당 중량", "attributeValueName": "1.5kg"}와 같이 명시적인 키-값 쌍을 생성해야 한다. 이미 등록된 상품의 경우 sellerProductItemId를 키로 하여 부분 수정(UPDATE) API를 호출한다.  
* **네이버 (SmartStore API):** origin 필드에는 ISO 국가 코드(예: KR, CN)가, weight 필드에는 정수형(kg 단위) 데이터가 요구된다. Tavily 결과가 "Made in Vietnam"이라면 이를 "VN" 코드로 변환하는 국가 코드 매퍼(Mapper)가 미들웨어 단에 구현되어야 한다.

## **6\. 결론 및 향후 전망**

이커머스 데이터의 불완전성 문제는 물류 비용 상승과 규제 준수 리스크라는 실질적인 비용을 발생시킨다. 본 보고서에서 제시한 **Tavily API 기반의 지능형 데이터 증강 전략**은 기존의 수동적이고 파편화된 접근 방식을 넘어, **(1) 도메인 신뢰도에 기반한 정밀 검색**, **(2) LLM을 활용한 문맥적 속성 추출**, **(3) 다차원 검증 알고리즘을 통한 데이터 정합성 확보**를 가능케 한다.

특히, 아마존과 같은 글로벌 마켓플레이스의 정형 데이터와 매뉴얼 라이브러리의 비정형 데이터를 결합하고, 이를 HS Code 분류 및 단위 변환 로직으로 정제하는 파이프라인은 크로스보더 셀러들에게 강력한 경쟁 우위를 제공할 것이다. 향후에는 단순한 텍스트 검색을 넘어, 상품 이미지만으로 3D 부피를 추정하거나, 포장재 재질을 시각적으로 분석하는 멀티모달 AI 에이전트 기술이 이 분야를 더욱 고도화할 것으로 전망된다. 기업과 셀러는 이러한 자동화 기술을 선제적으로 도입함으로써, 운영 효율성을 극대화하고 글로벌 시장 확장에 따른 복잡성을 효과적으로 제어해야 할 것이다.
