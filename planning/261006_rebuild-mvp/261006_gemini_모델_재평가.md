1. 🔴 **rebuild(B)의 기본 모델 `gemini-2.5-flash`는 이 키로 호출할 수 없습니다.** `gemini-2.5-flash-lite`도 마찬가지입니다. 두 모델 모두 404 "no longer available to new users"를 반환합니다. `[실측]`

   - 설정 위치: `packages/config/src/index.ts:148`, 시드 `packages/db/src/seeds/app-config.seed.ts:17`.
2. A(kbuyer-v2)의 기본 모델 `gemini-3-flash-preview`는 동작합니다. 다만 preview 모델이라 정식(stable) 모델로 옮기는 게 좋습니다.
3. **역할별 권고:**

| 용도 | 권고 모델 | 근거 |

| 대량 상품 추출 (스크래핑 LLM 단계) | `gemini-3.5-flash-lite`, thinking `low` | 정확도가 상위 모델과 같고, p50 1.4초, 1천 콜당 $0.33 |
| 대화 에이전트 (도구 호출) | `gemini-3.7-flash` (기본 또는 `low`) | 도구 선택 10/10, Flash급 중 가장 빠르고 쌈. 단 2027-01부터 가격 2배 |

### 틀린 곳
- **R1 무신사 가격 — 모든 모델이 23,920원으로 답했습니다.** 정답은 판매가 29,900원입니다.

  - 교훈: 구조화 데이터(JSON-LD, 내장 상품 JSON)를 먼저 읽고 LLM은 그다음 단계에서만 쓰는 B의 추출 순서가 맞습니다. 운영 A 채팅도 이 상품을 ₩29,900으로 표시했는데, 구조화 데이터를 읽었기 때문입니다.
- **HS 오답:**
  - 응원봉: 3.1-flash-lite는 8543, 3.5-flash-lite 기본 설정은 8518로 답했습니다.
  - 초코바: 3.5-flash-lite 기본 설정은 1704(설탕 과자)로 답했습니다.
  - lite 모델은 애매한 품목에서 흔들립니다. HS는 어떤 모델을 쓰든 1차 추정으로만 두고, B 설계대로 검증 게이트와 사람 검토를 거쳐야 합니다.

## 4. 적용 권고

1. **B 기본값 교체:** `gemini-2.5-flash` → `gemini-3.5-flash-lite` + thinking `low`. ✅ **2026-10-06 로컬 사본(`kbuyer-latest`)에 반영했습니다.** 커밋과 푸시는 하지 않았습니다.
   - 반영 내용: 단일 상수 `FALLBACK_LLM_MODEL`·`FALLBACK_LLM_THINKING_LEVEL` 도입, 새 AppConfig 키 `llm.thinkingLevel`, `GeminiLlmClient`의 `thinkingLevel` 옵션, 워커 연결, 시드, `.env.example`, EXTERNAL_INTEGRATIONS 문서, ADR `rebuild/docs/01_Architecture/ADR/2026-10-06_gemini-model-refresh.md`.
   - 검증: 전체 빌드 11/11, 테스트(config 30 · providers 221 · worker 37) 통과, lint 통과, docs:check 통과, 실제 키로 라이브 호출 통과(1.4초).
   - ⚠️ 이미 만들어진 DB는 시드가 기존 값을 덮어쓰지 않습니다. 그래서 `llm.model = gemini-2.5-flash` 행은 직접 바꿔야 합니다.
2. **A 운영 기본값:** `gemini-3-flash-preview`(preview)에서 stable 모델로 옮깁니다. 운영 Vercel env와 AdminSettings 값을 함께 확인해야 합니다.
3. **에이전트 신규 설계 시:** `gemini-3.7-flash`로 시작합니다. 모델 ID는 하드코딩하지 말고 AppConfig로 바꿀 수 있게 둡니다(B 구조 그대로).
4. **thinking 수준을 설정값으로 노출합니다.** 같은 모델이라도 `low`로 두면 Flash 계열 비용이 절반 안팎으로 줄었습니다(3.7-flash 기준 $1.70 → $0.88).
5. **결정 전 재측정:** 실제 페이지 50~100개로 라벨 코퍼스를 만듭니다. 대상은 쿠팡, 무신사, 올리브영, 알라딘, 위버스, 29CM 등입니다. 이 코퍼스로 B의 `crawl-cost-harness`를 돌려 필드별 자동 검증률을 봅니다. 쿠팡은 단순 요청을 403으로 막고 있어, 수집에 브라우저 기반 fetch가 필요합니다. `[실측]`
