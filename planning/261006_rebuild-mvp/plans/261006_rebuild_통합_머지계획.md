### 1.2 이 계획이 따르는 전략 제약 (v0.3)

- **고객과 시장** `[문서]`
  - 1순위 고객: 해외 K-Culture 팬. 주문당 $80~200 `[가정]`. 해외 거주 한국인은 1차 비대상(영어 UI · 의약품 금지 · 검역).
  - 진입 채널: Reddit, Discord. 초기 할인은 **Shopify 할인 기능**(P-8 확정 — 수수료율 플래그 아님).
  - 초기 시장: 미국. 역직구 비중은 미국이 38%. B의 랜딩 기본값도 미국이다.
  - → **미국을 먼저 연다.**
- **KPI** `[문서]`
  - 깔때기: URL→장바구니 ≥25%, 장바구니→결제 ≥60%
  - 정확도: 관세 견적 오차(주문당 $1 이내, 관세 > 0 이면 5% — RT-16), 통관 실패 ≤0.5%, 가격 변동률
  - 비용·운영: 스크래핑 ≤$0.03/상품, 주문당 운영 처리 ≤8분, CS 1차 응답 24시간
  - → M4 출시 대시보드 항목이 된다.
- **단위 경제**
  - 수익원 4종 모두 MVP(확정): ① 국제 배송 마크업(`shipping.markupRate`, 초기 10% `[가정]`) ② 환율 마진(`fx.spreadRate`, 초기 0.5% `[가정]`) ③ 부가세 영세율 환급(견적 미반영, 세무사 확인) ④ 최저가 결제 차익. 수수료 = 상품가 × 10%, 최소 $5(S3).
  - 인프라 예산: **월 $100 이하**(S8 · D9 확정, Shopify 구독료 · 결제 수수료 제외).
  - 손익분기는 03 PRD 단위 경제 절에서 다시 계산한다 `[가정]`(옛 "월 300건 · 고정비 $3K" 는 쓰지 않는다).
- **일정**
  - 원래 일정(첫 매출 2026-08-12 등)은 **달성 기록이 없다** `[실측: 2026-05-20 이후 kbuyer-v2 커밋 없음, 운영 주문 0]`.
  - → 새 일정은 §0 표(변경 시트 §1.2). **첫 실매출 = 2027-01 말(G0 후 약 16주).**
- **의사결정** (D10 확정)
  - **최종 결정 = 박요한.** 개발 = 인수 개발자(GitHub `DongHeeKw`) + AI. 김도윤 = 자문 · 리뷰(선택).
  - 결제, 개인정보, 약관, 광고에 관한 변경은 `legal-team` 검토 필수. 약관 개정은 [약관 개정안 목록](261007_약관_개정안_목록.md) → 변호사 검토 후 반영.

### 1.3 왜 "git merge"가 아니라 "이식"인가 `[실측]`

- A·A'는 Next 단일 앱이고, B는 모노레포다. 스키마와 상태 머신이 서로 다르다. 그래서 기능 단위로 다시 쓴다.
- A·A' 라우트 대부분에 상태 가드와 감사로그가 없다. 그래서 화면만 가져오고 로직은 B 서비스에 연결한다.
- **운영 A DB에는 주문 0건, 견적 0건, 사용자 1명뿐이다.** 그래서 고객 데이터 이관은 필요 없다.
- B의 lint 규칙 `no-hardcoded-money`는 `1400 / 0.10 / 6000 / 800` 같은 금액 리터럴을 config 밖에서 쓰지 못하게 막는다. A 코드를 그대로 옮기면 CI가 깨진다. 이식할 때 값은 config에서 읽게 바꾼다.

**이식 규칙 (모든 PR 공통)**
1. PR에 출처를 적는다: `ported from <A|A'>:<path>@<commit>`
2. B의 CLAUDE.md 규칙을 따른다.
   - 입력 검증: Zod
   - 상태 전이: domain 계층에서 검증
   - 관리자 변경 작업: 감사로그 테스트 포함
   - 기한 필드: sweeper로 처리
3. 이식 1건 = PR 1건. 작성 = 인수 개발자 + AI. 머지 판단 = 박요한(정책 · 돈 · 법무 영향 PR 은 반드시). 김도윤 리뷰는 요청할 때만(선택).
4. **B의 단계 관문을 그대로 쓴다.**
   - 앞 단계 게이트가 통과해야 다음 단계로 간다.
   - 예외가 필요하면 ADR로 남긴다(S4 는 ADR `2026-10-07_shopify-hybrid-ledger`).
   - 출시 관문은 Playwright e2e다.
