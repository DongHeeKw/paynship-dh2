- 원천 디렉토리 중 `master-plan/`, `prd/`, `roadmap/`, `dev/`는 비어 있었습니다. v2.2 README §2에는 계획만 적혀 있습니다. 그래서 실제 원천은 planning 12종, migration 3종, gap 2종, STATUS, researches 1종입니다. S4 확인을 위해 v2.0 ADR과 `03_SHOPIFY_API_DESIGN`도 읽었습니다.

  - 독립된 테스트 계획(QA)

## 2. S4 "Shopify가 주문 원장" 결정의 문서 영향

### 2.1 원천의 Shopify 원장 설계 요약

**정본 범위** (`V20/documents/Journal/[yohan v2.0] 2026-04-19_ADR_Shopify_Full_Backend.md` Decision §1~3)
- Shopify가 정본인 것: 고객(Classic 계정), 상품·옵션·재고, Draft Order → 결제 화면, 결제 앱, 세금·DDP, 배송·출고, 배송 추적 알림, 할인, 주문 상태(paid → fulfilled → delivered), 환불, 리포트.
- 자체 DB에 두는 것: 스크래핑, 카탈로그, 상품 미러, 9단계 발주, 컴플라이언스, 차지백, 감사로그, 대화.
- 동기화 규칙:
  - 구매 시 Shopify 고객 생성 → `User.shopifyCustomerId` 저장
  - 장바구니 담기 시 `productCreate`(72시간 TTL)
  - `orders/paid` 웹훅 → 자체 Order와 ProcurementTask 생성
  - `fulfillmentCreateV2`에 송장 첨부 → Shopify가 고객 알림 발송
  - 환불은 Refund API

**API 설계** (`V20/documents/master-plan/[yohan v2.0] 03_SHOPIFY_API_DESIGN.md`)
- §2.3 Draft Order `customAttributes`: `paynship_quote_id`, 수수료 규칙, `paynship_inspection_selections`, `paynship_exchange_rate_snapshot`, `paynship_fee_breakdown`. 수수료와 검수비는 custom line item(`taxable:false`, `requiresShipping:false`).
- §2.5 웹훅: paid, fulfilled, cancelled, refunded, updated, products/update.
- §2.6 박스마다 fulfillment를 따로 만듦.
- §3 상태 매핑: QUOTE_CONFIRMED = Draft(open), PAID = financial_status paid, 발주·입고 단계는 Shopify에 표현 없음, 2차 결제는 별도 Draft 또는 기존 주문 수정, SHIPPED = fulfilled.
- v1.1 배너의 자동 태그: New Order → Sourcing Inspected → Shipped_Intl → Delivered, Return_Requested → Return_Shipped → Resolved, Canceled_Penalty.
- §4: 재시도 규칙과 `ShopifyWebhookEvent` 기록.

**9-Step ADR**
- "Shopify 주문 상태만 쓰는 방식"은 기각했습니다. 중간 단계는 자체 상태 기계가 관리하고 태그는 보조로만 씁니다.
- 고객 알림 주체를 나눴습니다: 0단계와 1G~1I는 Shopify, 1B·1C·1F는 우리 메일.

**v2.2 조정** (`SHOPIFY_PLAN_MATRIX` §1B·§1C·§3, `planning/12` §0·§4.2)
- Basic 플랜이라 배송비와 DDP는 우리가 계산해서 Draft Order 줄로 넣습니다.
- 태깅은 자체 미들웨어, 권한은 자체 어드민이 맡습니다.
- 고객·할인·환불 같은 일상 작업은 Shopify Admin에서 합니다.

→ **해석 [추정]**: 원장 경계는 "주문·결제·환불·출고·고객·할인 = Shopify, 견적·발주·검수 운영 상태와 감사로그 = 자체 DB"인 하이브리드입니다. v2.0도 이 경계였습니다.
